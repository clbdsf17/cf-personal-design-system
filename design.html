Design System

CF Personal

An editorial, confident, warm personal-brand system where black acts and color expresses.

This page is the human-readable mirror of docs/design.md, which is the source of truth. Every swatch, specimen and component below renders from the same token values via CSS custom properties — nothing is hardcoded. When a token changes in the .md, change it here in the same edit so the two never drift.

02

Typography

Barlow sets display and headings; Inter sets everything else. Barlow is a slightly condensed grotesk with squared terminals — narrower and more technical than Inter, which gives the pairing a real width contrast. Hierarchy still comes mainly from weight, tracking, case and scale jumps. Barlow earns its place at 700–800 with moderate negative tracking: it is already narrow, so tracking it as hard as a wide geometric would collide its terminals.

Spacing

An 8px base with a deliberately non-linear top end. The large steps matter more than the small ones — the character of this system lives in its voids. Rhythm is: large void, tight cluster, large void. Uniform gaps are what make a layout read as a template.

04

Shapes

There are exactly two radius values. The absence of a middle option is the enforcement mechanism — there is no "slightly rounded" to reach for.

rounded-none

0px — buttons, inputs, cards, badges, images. Everything rectangular.

rounded-full

9999px — reserved for genuinely circular things, principally the pagination dot.

✗ 10px
Not a token. Not a judgment call.

Does not exist

Any radius between 0 and full is a bug. Rounding is the default gesture of every UI framework — it is the fastest route to Generic SaaS.

05

Elevation & Depth

There is no shadow scale. Depth is surface contrast and 1px borders — nothing else. Hover does not raise a card; it sharpens it.

Sunken

surface-sunken on background. Recessed blocks, callouts, code wells.

Base

The canvas itself. No border in production — the dashed outline here is only to show its extent.

Raised

surface on background plus a 1px border. A ~4% luminance step reads as separation with no blur at all.

Raised · emphasis / hover

Same fill, border swapped to border-strong. The plane stays flat while interactivity is still confirmed.

Note: the design.md component schema has no border property, so border values are specified in the Elevation prose of the .md and implemented here.

07

Do's and Don'ts

✓ Do

  • ✓Use action — black in light, off-white in dark — for every button, link and control.
  • ✓Pick exactly one expressive colour per composition, and let it appear as large geometry, not small decoration.
  • ✓Use expressive-overlap blue wherever a shape crosses a photograph, as a multiply blend.
  • ✓Set Barlow at 700–800 with moderate negative tracking (-0.01em to -0.02em), and keep it above 22px.
  • ✓Render label type in uppercase everywhere it appears.
  • ✓Vary spacing deliberately — tight clusters separated by large voids.

Black acts · one accent · flat surfaces

✗ Don't

  • ✗Don't apply any corner radius other than none or full. A 4px radius is a bug.
  • ✗Don't put an expressive colour on a button, link, chip or any interactive surface.
  • ✗Don't add shadows, gradients, glows, blurs, glassmorphism or illustrated blobs.
  • ✗Don't run two or more expressive colours in the same view.
  • ✗Don't use Barlow for body copy, captions or anything under 22px, below 600 weight, or tracked tighter than -0.02em.
  • ✗Don't use on-surface-subtle for body copy. It fails WCAG AA and exists for disabled states only.

Gradient · accent-on-control · rounded + shadow — all forbidden
